# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project status

DocSentinel is a deterministic-first documentation QA framework and Python library with three completed milestones:

- **Milestone 0001 (Generic implementation & Fast profile):** Rule registry, layered config discovery, baseline tracking, CLI/Python/pytest orchestration engine, and fast structural detectors (`DS101` dangling links/anchors, `DS102` stray HTML comments, `DS103` unresolvable paths).
- **Milestone 0002 (Standard profile):** Corpus-level detectors (`DS201` text complexity, `DS202` duplicate text, `DS203` low-information content, `DS204` docstring-to-code signature mismatch), lazy loading boundary, and separate baseline/CI lanes.
- **Milestone 0003 (Deep profile & Periodic review):** Semantic contradiction candidate detection (`DS301`), explicit opt-in confirmation gate (`deep_confirm` / `--i-understand-deep-is-heuristic` / `DOCSENTINEL_DEEP_CONFIRM=1`), advisory-only exit codes, and periodic review workflows.
- **Milestone 0007 (Template-driven reporting):** every report is rendered from a JSON template over a JSON-shaped context built by the `telemetry/` package (no hardcoded output format), `json` is now document-centric schema 2 (`json-v1` keeps schema 1), findings print under their document, and an extension API adds data to the context (`builtin:domain`, `builtin:document_stats`, opt-in `python:`). Milestone 0007 is in its closing story (05.0); ADR 0003 is still `Proposed` pending owner sign-off. The Milestone 0006 fault-event adapter, `telemetry_sink` and FaultEvent emission are NOT implemented yet.

## Commands

Requires Python 3.12+ and [uv](https://docs.astral.sh/uv/). Optional dependency extras are `test` (`pytest`), `standard` (`scikit-learn`, `textstat`, `docsig`), and `deep` (`spacy`, `textacy`).

```sh
uv sync --extra test --extra standard --extra deep
uv run pytest -p docsentinel.pytest_plugin          # full suite (same as CI)
uv run pytest tests/integration/test_scan.py::test_name -p docsentinel.pytest_plugin   # single test
uv run pytest tests/unit/                              # unit test suite
uv run pytest tests/mock/                              # mock test suite
uv run pytest tests/integration/                       # integration test suite
uv run docsentinel scan PATH --format json             # CLI scan; json = schema 2 (also: text, github, json-v1 = old schema 1, json-documents; --template PATH; --extension builtin:domain; --output/-o PATH writes the report to a file)
uv run docsentinel scan docs --link-root .              # base for /-links (trusted; overrides config link_root)
uv run docsentinel scan --profile standard             # standard profile scan
uv run docsentinel scan --profile deep --i-understand-deep-is-heuristic   # deep profile scan
uv run docsentinel baseline PATH --output PATH        # baseline recording
uv run docsentinel init                                # scaffold docsentinel.toml
uv run docsentinel rules                               # list available/active rules
uv run docsentinel doctor                              # environment and dependency readiness
uv build                                               # hatchling wheel/sdist
```

CI (`.github/workflows/ci.yml`) runs with `--locked`: sync with extras, pytest with the plugin, self-scans of the repo, and `uv build`. Self-scan reports are written with `-o reports/...` and uploaded as the `docsentinel-reports-py<ver>` artifact; `.github/scripts/print_report.py` logs a report only up to `REPORT_PRINT_MAX_FINDINGS` (default 15) findings, otherwise its finding count, line count and path plus the text `Blocking findings` recap (at most `REPORT_TAIL_LINES`, default 60). Never print a full report to the CI log.

## Architecture

All consumers go through one engine, so behavior stays identical across CLI, Python library, and pytest plugin:

- `config.py` — loads/validates `docsentinel.toml` or its alias `doc_sentinel.toml` (standalone; both in one root is a `ConfigError`) or `pyproject.toml` (`[tool.doc_sentinel]` table: `profile`, `include`, `exclude`, `select`, `ignore`, `baseline`, `max_grade_level`, `duplicate_similarity`, `min_information_score`, `docsig_paths`, the standard-profile statistical size limits `min_document_words`, `min_paragraph_words`, `min_paragraph_chars`, `deep_confirm`, plus the Milestone 0005 typed policy options `anchor_collision_policy`, `anchor_renderer`, `heading_level_policy`, `first_heading_level`, `multiple_h1_policy`, `setext_heading_support`, `empty_section_policy`, `placeholder_content_policy`, `image_content_counts`, `empty_section_min_text_chars`, `unused_reference_definitions`, `duplicate_reference_definitions`, `reference_label_normalization`, `fence_dialect`, `report_stray_closing_fence`, `require_fence_languages`, `allow_unlabelled_empty_fences`, `allowed_fence_languages`, `table_dialect`, `table_strict_cells`, `table_enable`, `navigation_indexes`, `navigation_required`, `navigation_unique_targets`, `navigation_check_missing`, `asset_extensions`, `check_html_asset_tags`, `check_markdown_images`, `check_srcset`, `root_escape_policy`, `decode_percent_paths`, `windows_path_policy`, `document_id_field`, `document_id_scope`, `document_id_case_sensitive`, `document_id_required`, `deprecated_references_file`, `deprecated_check_prose`, `deprecated_check_links`, `deprecated_case_sensitive`, `documentation_naming`, `documentation_naming_allow`, `documentation_naming_directories`, `documentation_naming_prefix_patterns`, plus the Milestone 0007 report options `report_templates_dir` (root-contained directory of extra templates, default none; lexically checked here, containment-gated by the template loader), `report_show_clean_documents` (bool, default false) and `report_include_run_meta` (bool, default false), plus `link_root`). These Milestone 0005 options are typed and validated; only the fence options (`fence_dialect`, `report_stray_closing_fence`), the fence-language policy options (`require_fence_languages`, `allow_unlabelled_empty_fences`, `allowed_fence_languages`, plus `fence_dialect` which gates DS110), the heading options (`heading_level_policy`, `first_heading_level`, `multiple_h1_policy`, `setext_heading_support`), the anchor options (`anchor_collision_policy`, `anchor_renderer`), the empty-section options (`empty_section_policy`, `placeholder_content_policy`, `image_content_counts`, `empty_section_min_text_chars`), the table options (`table_dialect`, `table_strict_cells`, `table_enable`), the path-boundary options (`root_escape_policy`, `decode_percent_paths`, `windows_path_policy`), the reference options (`unused_reference_definitions`, `duplicate_reference_definitions`, `reference_label_normalization`), the asset options (`asset_extensions`, `check_html_asset_tags`, `check_markdown_images`, `check_srcset`, `missing_asset_policy`) the navigation options (`navigation_indexes`, `navigation_required`, `navigation_unique_targets`, `navigation_check_missing`) the document-identity options (`document_id_field`, `document_id_scope`, `document_id_case_sensitive`, `document_id_required`) the deprecated-reference options (`deprecated_references_file`, `deprecated_check_prose`, `deprecated_check_links`, `deprecated_case_sensitive`) and the documentation-naming options (`documentation_naming`, `documentation_naming_allow`, `documentation_naming_directories`, `documentation_naming_prefix_patterns`) are consumed so far (by `DS109`, `DS110`, `DS105`, `DS104`, `DS106`, `DS117`, `DS116`, `DS108`, `DS113`, `DS112`, `DS114`, `DS115` and `DS118`); with `DS118` registered, every Milestone 0005 typed policy option is now consumed by a registered rule. `DS110` is an optional policy, off by default: it emits nothing unless `require_fence_languages` is enabled. `DS112` is also an optional policy, off by default: it emits nothing unless `navigation_indexes` names one or more index documents, and then consumes `navigation_required`, `navigation_unique_targets` (default on) and `navigation_check_missing` (default on). It scopes navigation to links on list items over the scanner's masked text (R1); reports a duplicate navigation target (`navigation_unique_targets`), a missing local destination (`navigation_check_missing`, `os.stat` only) and a target escaping the scan root (lexical, zero filesystem access, intentional DS116 overlap); and across indexes reports a `navigation_required` document that no navigation link points at. The README's "appear exactly once" is the union of the presence check (`navigation_required`) and the uniqueness check (`navigation_unique_targets`, default on), not one coupled rule. A missing/unreadable/non-regular/out-of-root/non-discovered configured index is a fail-closed `ConfigError` (readiness error, CLI exit 2), never a finding and never a silent clean result. `DS117` is an always-active fast rule: it validates GFM pipe tables unless `table_enable` is false or `table_dialect` names an unsupported dialect. `DS116` is an always-active fast rule at error severity: it reports references that escape the scan root and consumes `root_escape_policy` (off/warn/error), `decode_percent_paths` and `windows_path_policy`. Its code-span scope is narrowed (Story 11.0 ruling): links, images, reference definitions and HTML `href`/`src`/`srcset` are checked at full strictness, but inline code spans report only genuine traversal (root escape or in-root symlink-out) and leave drive/UNC/backslash/control and regex/escape spans to DS103. `DS108` is an always-active fast rule at warning severity: it checks reference-style link/image identifiers and definitions (undefined full/collapsed references and duplicate definitions, the latter gated by `duplicate_reference_definitions` off/warn/error), reports unused definitions only when `unused_reference_definitions` is enabled, and models only the `commonmark` `reference_label_normalization` dialect; it checks label identity, never target existence (that is DS101's concern). `DS113` is an always-active fast rule at error severity: it reports local media and document assets that do not exist as a regular file inside the scan root -- Markdown images, HTML `<img>`/`<source>` `src`/`srcset`, HTML `<a href>` and used reference-definition targets. Images are checked regardless of extension; `asset_extensions` (case-insensitive) gates only link-shaped references, the three `check_*` toggles enable/disable each reference kind, and `missing_asset_policy` (off/warn/error, default error) downgrades or silences it without changing the Rule metadata severity. It reuses the shared resolver, defers every DS116-owned or symlink-out target to DS116 (never stats an escape), and decides existence/type with `os.stat`+`S_ISREG` only (never opens content). `DS114` is an always-active fast rule at error severity: it reports two documents that declare the same stable frontmatter identity within `document_id_scope` (`corpus`/`directory`), reading only the configured `document_id_field` with its own minimal, bounded, stdlib-only frontmatter reader (no YAML dependency; DS111 is not in this tree). Values are normalized to NFC with whitespace collapsed, and case-folded when `document_id_case_sensitive` is false; `document_id_required` additionally flags each document lacking an identity. It stays silent for `DS111`-owned malformed metadata (an unterminated/over-long opening block, or a duplicate id key) but emits ONE explicit finding when the configured field is present in a well-formed block with an unsupported value shape (flow/anchor/tag/block scalar/nested/unterminated quote), excluding that document from collision detection — a finding, never a `ConfigError`, so one odd document never aborts the scan. `DS115` is an optional policy, off by default: it emits nothing unless `deprecated_references_file` names a root-contained TOML mapping of `[[replacement]]` entries (`old`, `new`, `kind` from `prose`/`link`/`identifier`, optional `scope` globs). When set it reports each in-scope textual occurrence of a mapped `old` token with the suggested `new` and the mapping provenance: `prose`/`identifier` are gated by `deprecated_check_prose` (prose over the scanner's masked text, identifiers over inline code), `link` by `deprecated_check_links` (local link / reference-definition targets, matched lexically with zero filesystem probing of the target), and `deprecated_case_sensitive` governs the single case policy (NFC normalization, no confusable folding). `old` tokens are matched literally with whole-token boundaries (never compiled as a regex); a missing/unreadable/non-regular/out-of-root/oversized/unparseable/schema-invalid mapping (including a cross-entry duplicate `old`) is a fail-closed `ConfigError` (readiness error, CLI exit 2), never a finding and never a silent clean result. `DS118` is an optional policy, off by default: it emits nothing unless `documentation_naming` selects a style (`kebab`/`snake`). When set it validates the relative POSIX path of each discovered document against a portable-ASCII naming policy -- lowercase ASCII letters/digits joined by the style's single separator per path component -- exempting the `documentation_naming_allow` filenames (default `README.md`/`index.md`, matched by basename or whole relative path) and the `documentation_naming_prefix_patterns` glob exceptions (a restricted literal/`?`/`*` subset, never a regex, for numeric ADR prefixes), checking directory components only when `documentation_naming_directories` is true, and reporting once per offending component (directories outermost-first, then the file) with a deterministic ASCII suggested rename. It is a pure path-string policy with zero filesystem access that never reads document content and never renames a file (DS101 reports any link a later user rename breaks); the offending name is echoed bounded and `unicode_escape`-ed, and an injected `Config` with an unrecognised style or out-of-bounds prefix patterns fails closed with a `ConfigError`. The existing standard-profile keys `max_grade_level` (DS201), `duplicate_similarity` (DS202), `min_information_score` (DS203) and `docsig_paths` (DS204) are joined by three statistical size limits consumed in the standard profile: `min_document_words` (int >= 1, default 50; DS201 skips documents with fewer prose words), `min_paragraph_words` (int >= 1, default 5) and `min_paragraph_chars` (int >= 0, default 30) (DS202/DS203 skip paragraphs below either floor; the two floors form part of the `build_corpus_model` lru_cache key so distinct settings never share a stale corpus). Defaults reproduce historical behaviour byte-for-byte. The Milestone 0007 extension options are `telemetry_extensions` (list of `builtin:<name>` specs, at most 32; a `python:` entry is a `ConfigError`) and `telemetry_domains` (array of `[[telemetry_domains]]` tables `glob`/`domain`, tried in order, first match wins, fallback `docs`; at most 256 entries, 256 characters and 32 segments per glob, 4096 glob characters in total; the domain label matches `^[a-z][a-z0-9_-]{0,63}$`), both validated at load and again by `domain_for` for an injected `Config`. The site-root link base is `link_root` (string, default `"auto"`: the nearest ancestor of the scan root, itself included, holding a `.git` dir or file, found with `lexists` only, else the scan root; or a path relative to the scan root naming the scan root or an ancestor, bounded because a config file is untrusted: not above the nearest `.git` ancestor when there is one; otherwise an ancestor only if that exact directory directly contains a pyproject.toml, docsentinel.toml or doc_sentinel.toml file (`lexists` only, `link_root.PROJECT_MARKERS`); never the filesystem root; a `.git` ancestor that is the home directory or above (`os.path.samestat`) is untrusted, so `auto` falls back to the scan root and a configured ancestor is a `ConfigError`; anything else is a fail-closed `ConfigError`, also for an injected `Config`). The trusted invoker override is `scan --link-root PATH` / `baseline --link-root PATH` / `docsentinel.scan(..., link_root=PATH)` (`link_root.resolve_invoker_link_root`): absolute or CWD-relative, realpath-resolved, an existing scan root or ancestor, no `.git` or marker requirement, only the filesystem root refused; it wins over the config; never put it in pre-commit `args:` or a `pull_request_target` workflow. Only site-root-absolute (`/`) targets resolve against it, in DS101, DS103, DS112, DS113 and DS116, through `resolve_local_reference(..., link_root=)`. The engine alone probes the filesystem for it: `link_root.resolve_link_root` (config) runs once per scan, only when a rule in `link_root.LINK_ROOT_RULES` is active (an invoker override is always validated), and the validated directory is passed as a `link_root=` keyword to analyzers that declare it (the config is never rewritten); a detector called without it uses the lexical `link_root_for`, which accepts only values meaning the scan root and refuses any explicit ancestor. A `/` target inside the link root is not a DS116 escape even outside the scan root, one whose `..` climbs above it is, and `ResolvedReference.boundary` (`compare=False`) names the symlink-containment root. DS101 reads anchors of a linked file only up to 1,000,000 characters and skips the anchor check for a larger or non-UTF-8 file. `"auto"` trusts the enclosing repository; use `link_root = "."` for untrusted content nested in another checkout. Configured-path checks (DS112 indexes, DS115 mapping, template dir) stay scan-root-bounded.
- `discovery.py` — inventories Markdown files; output order and paths are stable. Patterns match relative paths; exclude patterns also match directory names; symlinked files are skipped.
- `engine.py` — `scan()` is the single entry point used by the CLI, the Python API (`from docsentinel import scan`), and the pytest plugin. It runs discovery, resolves active rules for the requested profile, executes registered analyzers from the `ANALYZERS` registry, and applies baseline filters. Analyzers are called as `detect(root, documents)` or, when their signature accepts a third `config` argument, `detect(root, documents, config)` with the effective `Config` (the engine inspects the signature, so both forms are supported in every profile). `ScanResult.notice` counts only genuinely evaluated rules and names any active opt-in policy rule whose policy is off (e.g. `12 fast rule(s) evaluated; opt-in rule(s) not enabled: DS110 (set require_fence_languages), DS112 (set navigation_indexes), DS115 (set deprecated_references_file), DS118 (set documentation_naming).`); the notice is derived (via `engine.evaluated_notice`) from two defaulted structured `ScanResult` fields, `rules_evaluated: int = 0` and `opt_in_off: tuple[tuple[str, str], ...] = ()` (`(code, option)` pairs, rule-code order), so it stays byte-identical; JSON schema v1, exit codes, and `enabled_rules` semantics are unchanged.
- `rules.py` — the rule registry. `Rule` carries an optional `opt_in_option` field naming the `Config` option that enables an opt-in policy rule (empty for ordinary always-active rules), and `opt_in_satisfied(rule, config)` reports whether that policy is on (a truthy, non-`"off"` value). `DS110` registers with `opt_in_option="require_fence_languages"`, `DS112` registers with `opt_in_option="navigation_indexes"`, `DS115` registers with `opt_in_option="deprecated_references_file"` and `DS118` registers with `opt_in_option="documentation_naming"`. `DS116` registers WITHOUT an `opt_in_option` — it is an always-active, default-on fast rule at error severity. `DS108` likewise registers WITHOUT an `opt_in_option` — an always-active, default-on fast rule at warning severity whose `unused_reference_definitions`/`duplicate_reference_definitions`/`reference_label_normalization` options tune behaviour but do not gate registration. `DS113` also registers WITHOUT an `opt_in_option` — an always-active, default-on fast rule at error severity whose `asset_extensions`/`check_*`/`missing_asset_policy` options tune behaviour but do not gate registration. `DS114` also registers WITHOUT an `opt_in_option` — an always-active, default-on fast rule at error severity whose `document_id_field`/`document_id_scope`/`document_id_case_sensitive`/`document_id_required` options tune behaviour but do not gate registration. The shared scanner's `ResolvedReference.reason` field carries the typed sub-category (`drive`/`unc`/`backslash`/`control`/`template`/`glob`) that lets `DS116` separate unsafe targets from safe ones. `DS101` delegates every unsafe link target to `DS116` via `is_ds116_owned` rather than resolving or stat-ing it; `DS103` no longer calls `is_ds116_owned` — per the code-span ruling it skips only root-escape and symlink-out code spans (via `escapes_via_symlink`) and reports drive/UNC/backslash/control spans with its legacy behaviour.
- `detectors/` — modular rule analyzers:
  - `fast` (DS1xx): `links.py` (`DS101`), `comments.py` (`DS102`), `paths.py` (`DS103`), `anchors.py` (`DS104`), `headings.py` (`DS105`), `sections.py` (`DS106`), `references.py` (`DS108`), `fences.py` (`DS109`), `fence_languages.py` (`DS110`, opt-in policy off by default), `navigation.py` (`DS112`, opt-in policy off by default), `assets.py` (`DS113`, always-active, error severity), `document_ids.py` (`DS114`, always-active, error severity), `deprecated_refs.py` (`DS115`, opt-in policy off by default), `path_boundaries.py` (`DS116`, always-active, error severity), `tables.py` (`DS117`), `naming.py` (`DS118`, opt-in policy off by default). Standard library only (`DS115` adds `tomllib` for its mapping file); `DS104`, `DS105`, `DS106`, `DS108`, `DS109`, `DS110`, `DS112`, `DS113`, `DS115`, `DS116` and `DS117` build on the shared `markdown_blocks.py` scanner (`DS114` and `DS118` are the exceptions: `DS114` carries its own minimal frontmatter reader, and `DS118` is a pure path-string policy that reads neither the scanner nor the filesystem) (`DS116` reuses its `resolve_local_reference` resolver and never adds a second path resolver; `DS113` reuses the same resolver and the `is_ds116_owned`/`escapes_via_symlink` containment gate and never adds a second resolver either; `DS112` reuses the same resolver and containment gate and never adds a second resolver either; `DS115` reuses the same resolver and containment gate to re-validate its configured mapping path and never adds a second resolver either).
  - `standard` (DS2xx): lazy-loaded via `loader.py`: `complexity.py` (`DS201`), `duplication.py` (`DS202`), `low_information.py` (`DS203`), `signatures.py` (`DS204`).
  - `deep` (DS301): heuristic semantic checks in `contradictions.py` (`DS301`), `_triples.py`, and `deep_support.py`. Opt-in gated, advisory-only. `contradictions.py` registers DS301 eagerly (for rule listing/selection) and imports `_triples` (spaCy/textacy) lazily on the first deep scan call via `importlib.import_module`; `import docsentinel` and fast/standard scans never pull in spaCy.
- `code_discovery.py` — Python source discovery for `DS204` docstring verification against live AST signatures.
- `models.py` — `Document`, `Finding`, `ScanResult`. `Finding` carries optional report-only `column` (1-based, code points), `value` (only the offending token the message already echoes -- a link target or path, never a snippet; untrusted) and `type` (short category such as `dangling link`), all `None` by default, appended after `line` and declared `compare=False`, so finding/`ScanResult` equality, hashing and baseline fingerprints are unchanged. `DS101` (`dangling link`/`dangling anchor`, value = target), `DS102` (`stray html comment`, column only) and `DS103` (`unresolvable path`, value = path) populate them; other rules leave them `None`.
- `baseline.py` — computes SHA-256 finding fingerprints, loads/saves baseline JSON files, and filters known findings.
- `reporting.py` — a thin shim: `render(result, format="text", *, config=None, template=None, root=None, strict=False, extensions=(), allow_python_extensions=False)` resolves a template (`template` object or invoker path, else `format` as a template *name*, never a path), builds `ReportModel` and calls the template engine; it holds no format branch, layout literal or `json.dumps` (an AST tripwire test, `tests/unit/test_reporting_has_no_format_literals.py`, enforces this for `reporting.py` and `telemetry/engine.py`). A `TemplateError` surfaces as a chained `ValueError`. Packaged templates: `text` (findings under their document, clean documents hidden unless `report_show_clean_documents`, ending with a `Blocking findings: N` recap of every `rejected`-outcome finding, counted by the trusted context variable `blocking_count`), `github`, `json` (schema 2, the default JSON since Milestone 0007, decision D1), `json-v1` (the byte-identical schema-1 report) and `json-documents`. `neutralize_text` (re-exported from `telemetry.filters.neutralize`, the table the `neutralize`/`gha_*` template filters use) neutralises C0/C1/DEL controls, bidi format characters (U+061C, U+200E–U+200F, U+202A–U+202E, U+2066–U+2069), zero-width characters (U+200B–U+200D, U+FEFF), line/paragraph separators (U+2028/U+2029), and lone surrogates (U+D800–U+DFFF) in the text and GitHub annotation sinks; `cli.py` also routes CLI error lines (`Scan failed:` / `Baseline generation failed:`) through `neutralize_text`.
- `cli.py` — command-line interface (`scan`, `baseline`, `init`, `rules`, `doctor`). `rules` marks an opt-in policy rule as `DS110: Missing language labels on code fences [opt-in: set require_fence_languages]`, `DS112: Declared documentation navigation integrity [opt-in: set navigation_indexes]` `DS115: Deprecated names and migrated references [opt-in: set deprecated_references_file]` and `DS118: Documentation file and directory naming policy [opt-in: set documentation_naming]`; `doctor` counts them separately, e.g. `fast rules: 16 registered (4 opt-in, off unless configured: DS110, DS112, DS115, DS118)`, and lists the report templates (packaged, plus `report_templates_dir` ones from the current directory's config). `scan --format NAME` is free-form, validated against the discovered template names (packaged, then `report_templates_dir`); `--template PATH` (trusted invoker path, still through the loader's file gate) wins over `--format`; `--show-clean-documents` sets `report_show_clean_documents`. The template is resolved before the scan runs; every template error prints `Scan failed:` via `neutralize_text` and exits `2`. `scan --extension SPEC` (repeatable) adds a report extension: `builtin:<name>` needs no gate, `python:<module>:<callable>` is accepted ONLY on the command line and only with `--allow-python-extensions` or `DOCSENTINEL_ALLOW_PYTHON_EXTENSIONS=1` (exactly `1`, read only in `cli.py`). An admitted `python:` extension runs with full trust (not a sandbox), the origin check (refusing modules under the scan or project root, an editable or project-local install) is point-in-time, and an extension error exits `2`. Never set the env gate for a whole workflow or job, in a `pull_request_target` example, `.envrc` or pre-commit `args:`; use `--format github` for Actions.
- `telemetry/` — package behind every report. `events.py` (`FaultEvent`, `to_json_dict`, `SCHEMA_VERSION`, re-exported from `docsentinel.telemetry`; no production caller emits events until Milestone 0006), `classify.py` (`classify(finding, config, *, strict=False)` -> `Classification(fault_class, tier, outcome, domain)`; `FAULT_CLASSES` mirrors `fault-classes.md` row for row, enforced by a test; outcome `rejected` for errors (and warnings under strict), `advisory` for warnings and every deep finding; `domain` comes from `domain_for` and defaults to `docs`), `model.py` (`ReportModel.build(result, config, *, extensions=(), strict=False, model=None, report_include_run_meta=False)` -> the JSON-shaped template context of `docs/specs/report-template-format.md` §6, plus `CONTEXT_SCHEMA` with type and trust tags for the template loader and `ADVISORY_BANNER`; `build` raises `ValueError` for a `model` outside `MODEL_ID_PATTERN`), `filters.py` (stdlib-only bottom layer: the `neutralize`/`gha_property`/`gha_data` tables, `TemplateError`, and the runtime filter table `apply_filter`/`FILTER_NAMES`, which must equal `loader.FILTERS`), `loader.py` (`load_template(source, *, root=None, templates_dir=None, from_config=False)` -> an immutable, validated `Template`; a source matching `NAME_PATTERN` is a name resolved packaged-first (`telemetry/templates/<name>.json`, never shadowed) then under `templates_dir`, any other source is a path; config-named files and the dir pass the DS115 containment gate before any open; 256 KiB cap, strict UTF-8; validation rejects duplicate keys, unknown keys/variables/filters/operators, control/bidi code points, unbounded nesting, and -- in `text` templates -- an untrusted variable whose filter chain does not end in a sink for the declared `output.sink`; not re-exported from `docsentinel.telemetry` to avoid an import cycle with `reporting.py`), `engine.py` (`render_template(template, context, *, extensions=())` -> `str`: logic-less text placements and json `$var`/`$default`/`$for`/`$if`/`$str`/`$omit_if` with `ensure_ascii` forced true, single-pass substitution, `MAX_OUTPUT_CHARS` (64 MiB) and `MAX_ITERATIONS` (5M) stop with `TemplateError` and never truncate; no file/env/clock access) and `extensions.py` (the extension API: `resolve_extensions`/`admit_extensions` -> `LoadedExtensions`, `ExtensionError`, hooks `provide_run`/`provide_document`/`provide_problem` whose JSON-shaped return lands under `ext.<name>` / `doc.ext.<name>` / `p.ext.<name>`, a template lists the names it needs in `requires_extensions`; `EventHookGuard` has no production caller yet). `telemetry/builtin/` holds the gate-free builtins: `domain` (sets the core `doc.domain` from `telemetry_domains` via `domain_for`, the single source also feeding `Classification.domain`; a regex-free `**`/`*`/`?` matcher; the label is asserted by the scanned repo, not verified) and `document_stats` (`doc.ext.document_stats.problem_count_per_kb`, `ext.document_stats.worst_documents`). `telemetry/templates/` ships the five packaged templates as package data (wheel and sdist): `text.json`, `github.json` (one well-formed `::error`/`::warning` command per problem, adds `title=<rule>`), `json.json` (schema 2, every document with `problems`, `domain` default `docs`). User guide: `docs/user/tutorial/custom-reports.md`; format contract: `docs/specs/report-template-format.md`.
- `pytest_plugin.py` — opt-in pytest plugin (`-p docsentinel.pytest_plugin`) exposing the `docsentinel_scan` fixture.
- `.pre-commit-hooks.yaml` — `docsentinel-fast` (default pre-commit) and `docsentinel-standard` (manual stage).

CLI exit codes: `0` = scan succeeded with no blocking findings (or advisory-only deep findings), `1` = blocking findings (errors, or warnings with `--strict`), `2` = config or scan failure.

## Conventions

- Deterministic-first: fast and standard detectors are strictly deterministic. Deep profile is heuristic, requiring explicit opt-in confirmation (`deep_confirm = true`, `--i-understand-deep-is-heuristic`, or `DOCSENTINEL_DEEP_CONFIRM=1`), and is advisory-only (exit code 0).
- Profiles: `fast` (structural/reference checks, stdlib-only at scan time; note: `pyproject.toml` lists `spacy` as a core dependency — always installed but not imported during fast or standard scans, and removing it is an open product decision), `standard` (corpus/signatures, `docsentinel[standard]`), `deep` (semantic contradictions, `docsentinel[deep]`). Profiles are exact rather than cumulative.
- Rule selection: exact codes or prefixes via `select` / `ignore` (e.g. `select = ["DS1"]`).
- No hardcoded output format: every report layout lives in a template (`telemetry/templates/*.json` or a user template), never in `reporting.py`, `telemetry/engine.py` or a detector; the AST tripwire test enforces it. A new format is a new template, not a new branch. Untrusted values (paths, messages, `value`, extension output) reach a text sink only through a neutralizing filter. `doc.domain` is a repository-asserted label (default `docs`), never a verified ownership signal.
- Opt-in policy rules: some rules are inert until configured (`DS110` via `require_fence_languages`, `DS112` via `navigation_indexes`, `DS115` via `deprecated_references_file` and `DS118` via `documentation_naming`). They are reported as such and never presented as ordinary evaluated rules — `ScanResult.notice` excludes an off opt-in rule from the evaluated count and names it, `docsentinel rules` tags it `[opt-in: set <option>]`, and `docsentinel doctor` counts opt-in rules separately. Selection stays orthogonal: an opt-in rule can be in `enabled_rules` yet emit nothing until its policy is on.
- Test layout: `tests/unit/` tests one function with tiny inline strings and never loads assets; `tests/mock/` replaces an external resource; `tests/integration/` runs a detector, scan, or CLI over text assets kept in `tests/assets/` as one directory per rule code and case (dsNNN/case), loaded with the `asset_case` fixture. Integration files that load assets carry the rule IDs as a suffix (for example `_ds101`, or `_ds101_ds102_ds103` when composing rules). See `tests/assets/README.md`.
- Rule table: `docs/user/reference/rules.md` is the single table of checks, the source of truth for rule metadata in docs. `tests/integration/test_rules_table.py` keeps it equal to the `Rule` registrations, `FAULT_CLASSES`, the `Config` fields and the `docsentinel rules` listing; adding or changing a rule updates its row in the same change.
- Diagrams: an architecture change (module/package added, removed or renamed, responsibility moved, contract, pipeline or profile boundary changed) updates `docs/diagrams/` through the `diagram-creator` agent; `app-architect` names the affected diagrams (or reports a `Diagram impact` line when it runs as a subagent).
- Docs sync: after a change set that changes rule behaviour, the CLI, config, report output, the public API, the architecture or the dev workflow (triggers R/C/K/O/P/A/D in `docs/dev/documentation_sync.md`), run the `docs-updater` agent **once**, after the tests are green (and any review is LGTM) and before the push. Brief it with the change set and the implementer's `Docs impact` line. This applies to changes made directly in the main session too. Subagents cannot start it: `python-expert` only reports the line.
- See `docs/architecture/README.md` and `docs/roadmap/README.md` for architectural design and milestone details.
